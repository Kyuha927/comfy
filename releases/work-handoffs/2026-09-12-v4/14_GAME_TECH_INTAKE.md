# ONE-SHOT WORK HANDOFF — SoL-Pi / sprite-gen / New Game Tech Intake

## Model routing
- MAIN R&D owner: **GPT-5.6 Sol — High**
- Integration feasibility/implementation: **GPT-5.6 Sol — High**
- Architectural escalation judge: **GPT-6 Astra — High only when a candidate could alter the canonical core**
- Reproducibility/smoke tests: **GPT-5.6 Terra — Medium**
- Repository scouting and metadata extraction: **GPT-5.6 Luna — Medium**
- Never use Pro in Work.

This is the R&D intake lane for SoL-Pi, sprite-gen, and newly discovered game/graphics repositories. It is not the canonical game architecture.

For each candidate inspect the actual current repository, identify unique capability, assess maturity/maintenance, test the capability where feasible, compare with what already exists, estimate integration cost, and classify ABSORB NOW / EXPERIMENT / WATCH / REJECT.

Luna scouts broadly. Sol performs serious technical evaluation and any minimal integration. Terra runs smoke/repeatability tests. Astra is invoked only when adoption would materially change the canonical architecture.

Avoid duplicate systems and dependency sprawl. If a candidate is clearly valuable, implement the smallest clean adapter or produce a precise handoff into the Game Development Core. Maintain a decision log so the same repository is not repeatedly re-evaluated from zero.
