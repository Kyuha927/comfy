# 2. Control-plane rule

Do not encode the workflow as a rigid percentage such as “99% Computer Use.” Route by operation type while preserving the overall creative control order.

```text
VISUAL / SPATIAL / INTERACTIVE / SUPERVISED:
  GPT-6 Astra XHigh Computer Use

DETERMINISTIC / REPEATED / STATE-SENSITIVE / AUDITABLE / RECOVERABLE:
  Blender Bridge/MCP or reviewed deterministic Blender operation

HARD RIGGING / SKINNING / DEFORMATION / TOPOLOGY ENGINEERING:
  GPT-5.6 Sol High

INDEPENDENT TECHNICAL AND REGRESSION QA:
  GPT-5.6 Terra High

BOUNDED INVENTORY / HASHES / MANIFESTS / RECEIPTS:
  GPT-5.6 Luna Medium

EXACT COMPARISON / SCRIPTED VALIDATION:
  no LLM

SIMPLE MANUAL BLENDER PLACEMENT OR CLEANUP:
  allowed when faster or safer, but recorded and independently verified
```

Computer Use is the primary interactive visual lane. Bridge/MCP is not the default creative GUI operator, but it is authoritative for exact state-critical operations, transaction safety, durable jobs, checkpoints, rollback, and receipts.

Never silently replace unavailable Astra Computer Use with an MCP-primary creative loop. Return the exact blocker and continue only independent safe work.

# 4. Tripo source strategy

Choose exactly one source strategy.

## Route A: `DEDICATED_PART_REFERENCES`

Use only when complete approved packets exist for:

```text
HEAD
HAIR
BODY_CLOTHING
```

Generate separate Tripo candidates, preferably with Smart Mesh P2.0 when available and locally validated. Dedicated production hair requires approved front, left, right and back references. A single-view hair result remains provisional.

## Route B: `FULL_BODY_MULTIVIEW_PART_AWARE`

Use when exact full-body multiview masters are approved but locked source images may not be edited or complete part packets do not exist.

```text
exact approved full-body multiview inputs
-> Tripo full-body candidate
-> geometry acceptance
-> Tripo Generate in Parts or copied-candidate Segmentation v2
-> logical HEAD / HAIR / BODY_CLOTHING / accessory inventory
```

Do not crop, redraw, retouch, recolor, inpaint, synthesize missing views, or otherwise change locked source bytes unless the exact project task authorizes that derivative operation. Never destructively segment the only accepted 3D candidate.

# 5. Geometry before texture

Texture generation is a post-geometry acceptance transition.

For every candidate, inspect the exported mesh rather than only provider thumbnails. Preserve provider job IDs, model/version, input hashes, export hashes, polygon/triangle counts, rejected-candidate reasons, texture state, segmentation strategy, quota use and licensing/export metadata.

## Head gate

- soft start near 2,000 to 5,000 polygons unless another budget is justified;
- actual recessed orbital structure rather than painted-flat eyes;
- independently addressable eyeballs and pupils/irises or a cleanly separable equivalent;
- usable eyelids, mouth support, jaw, ears and neck opening;
- reject fused eyes, duplicate facial shells, collapsed planes, identity loss and topology that blocks rigging.

## Hair gate

- dedicated production candidates require front, left, right and back references;
- compare side and rear silhouette against every authoritative view;
- reject fused ears or collar, helmet-shell volume, floating attachments, repeated strand noise and invented rear structure;
- preserve logical masses for later rigging or secondary motion.

## Body and clothing gate

- verify complete anatomy and exactly two arms even when an orthographic side view visually occludes the far arm;
- reject fused, duplicate, detached or missing limbs and flat-image shells;
- preserve garment and material separation, attachment logic and the locked silhouette.

Do not texture a weak candidate merely to make rejection or regeneration more expensive.

# 6. Blender assembly and supervision loop

Use a private candidate copy, never the only proven source or an unrelated open scene.

```text
import accepted Tripo candidate or parts
-> inspect viewport and Outliner
-> align scale, axes, origin and proportions
-> assemble or validate logical head, hair, body/clothing and accessories
-> resolve scalp, neck, collar and garment intersections
-> preserve approved silhouettes
-> configure or repair armature, weights, constraints and secondary motion
-> render fixed views
-> compare against approved references
-> name the smallest visible defect
-> apply one bounded correction
-> verify scene state and pixels
-> checkpoint or rollback
```

Do not use one giant unattended prompt. A user or supervising operator must be able to steer the run between visible checkpoints.

A simple manual placement or cleanup is valid when faster or safer than spending model tokens. Record edited objects, before/after revision, operator action and verification evidence. Manual work does not waive render, save/reopen or rollback gates.

# 8. Neck, expression, rigging and secondary motion

Do not force destructive head-body welding merely to hide a seam. First align scale, centerline, neck opening, normals, materials and shading. Separate aligned meshes may pass when required cameras and deformation tests show no functional defect. If joining is required, duplicate the candidate, preserve rollback, inspect both loops and verify identity, UVs, normals, weights, materials, expressions and save/reopen stability.

Do not force shape keys before topology correspondence is proven. The initial stable expression route may use discrete expression-head mesh/state switching. Preserve identity, origin, neck alignment, eye placement and material assignment across expression heads. Promote to shape keys or a facial rig only after interpolation, save/reopen and regression evidence pass.

Astra Computer Use may supervise the first rigging and secondary-motion pass. Escalate hard topology, skinning, deformation or cross-module failures to Sol High. Any custom app, add-on, helper script or rig template is a declared dependency with name, version, configuration, commit or hash, license and availability. Never hide its absence or substitute another path silently.
